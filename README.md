# Голосовой ассистент для входящей телефонной линии

Робот принимает входящий звонок, распознаёт свободную речь клиента, понимает,
**новый это заказ или вопрос по уже оформленному**, находит тему по смыслу,
задаёт один уточняющий вопрос и переводит человека в нужный отдел. Работает на
живых звонках сервисной компании с сентября 2026 года.

Распознавание, поиск по смыслу и синтез работают на собственных моделях без
платных облачных сервисов. Голос бота — записанные заранее фразы, склонированные
с голоса живого оператора.

> Репозиторий подготовлен для публикации: внутренние адреса, имена хостов,
> логины и фамилии заменены плейсхолдерами (`10.20.0.x`, `voice-a`, «аналитик КЦ»).
> Корпус реплик клиентов, записи звонков и библиотека голосов в репозиторий не
> входят.

## Зачем это делалось

Компания ремонтирует бытовую технику и электронику. На входящей линии оператор
первым делом выясняет одно и то же: какая техника, что случилось и не звонит ли
человек по уже сделанному заказу, и переводит звонок в профильный отдел. Это
дорогая и однообразная работа.

До проекта распознавание речи покупалось у облачного провайдера. Задача была
двойная: убрать эту статью расходов и снять с операторов первичную сортировку.

## Как устроено

```
Клиент → Asterisk → EAGI: тонкий AGI-клиент (Python 3.9)
                     │
                     ├── gRPC, поток PCM 8 кГц ──→ речевой сервис
                     │                              VAD → распознавание
                     │                              → kNN по корпусу живых звонков
                     │                              → формулировки базы знаний
                     │                              → записанный голос / синтез
                     │
                     └── HTTP ──────────────────→ ERP: обращение, тема, перевод,
                                                       неопознанные вопросы на разметку
```

**Тонкий клиент на станции.** Скрипт живёт ровно один звонок и не содержит
логики диалога: гонит аудио в сервис и исполняет присланное действие. Asterisk
запускает отдельный процесс на каждый звонок, грузить в него модели нельзя.

**Речевой сервис — отдельный демон.** Модели грузятся один раз при старте и
обслуживают все звонки. База знаний приезжает из ERP толчком раз в десять минут
и подменяется одной операцией; копия лежит на диске, чтобы пережить перезапуск.

**Два мнения о реплике.** Сначала слово берёт корпус: 240 тысяч живых звонков,
размеченных по тому, в какой отдел они в итоге ушли. По пятнадцати ближайшим
соседям реплики корпус голосует за направление. Если он уверен, уточняющий
вопрос берётся из записи базы знаний этого направления. Если нет, решают
формулировки базы знаний по косинусной близости. Для повторных обращений
(«мне мастер звонил», «я у вас заказывал») корпус переразмечен классификатором,
обученным на четырёх тысячах реплик, разобранных вручную: такие звонки уходят в
сопровождение без вопросов.

**Диалог короткий и устойчивый.** Один уточняющий вопрос, ответ «да» или «нет».
Отказ проверяется раньше согласия, иначе «нет, мне нужно другое» засчитывалось
за «да». Непонятный ответ переспрашивается без потери темы; ответ, который сам
называет тему, считается согласием. Второй промах по теме — перевод на
оператора, а не третий вопрос.

**Голос — записанный, а не синтезированный.** Все фразы бота заранее
сгенерированы CosyVoice 3 на видеокарте с эталонов голоса оператора, по восемь
дублей на фразу с автоматическим отбором распознаванием (слово в слово плюс
проверка на обрывки в начале). Правило одно: весь набор фраз группы линий звучит
одним голосом или не звучит вовсе; не хватает хотя бы одной фразы — вся группа
временно говорит синтезом, а недостающее пишется в лог.

**Повторный звонок после сброса — сразу к человеку.** Если клиент бросил трубку
на боте и перезвонил в тот же день, ERP велит скрипту бота не включать: звонок
уходит оператору по направлению линии без приветствия.

## Что внутри

| Компонент | Выбор | Почему |
|---|---|---|
| Распознавание | GigaAM v3 (RNNT) | вдвое быстрее Vosk при равном качестве на телефонных 8 кГц |
| Детектор речи | Silero VAD | отделяет реплику от пауз в потоке |
| Поиск по смыслу | ru-en-RoSBERTa | эмбеддинги реплики, формулировок и корпуса |
| Голос | CosyVoice 3 (офлайн, GPU) + библиотека WAV | клон голоса оператора, фразы записаны заранее |
| Запасной синтез | Vosk-TTS | когда фразы нет в библиотеке |
| Транспорт аудио | gRPC | на станции нет `websockets`, а `grpcio` есть |

Движки распознавания и синтеза спрятаны за общими интерфейсами: смена — правка
переменной окружения.

## Измеренное

Сервис на виртуалке без видеокарты, 10 ядер Xeon E5-2690 v3, 25 ГБ RAM.
Видеокарта нужна только для разовой генерации голосовой библиотеки.

| Этап | Время |
|---|---|
| Пауза детектора речи до конца реплики | 1,0 с |
| Распознавание | 0,3–0,7 с |
| Корпус и формулировки (одно кодирование) | 0,35–0,45 с |
| Записанная фраза | ~0 мс |
| **Итого от конца фразы до ответа** | **≈ 2 с** |

Точность маршрутизации на 4000 реплик, размеченных вручную (два фолда):

| Показатель | Значение |
|---|---|
| Бот ответил, а не переспросил | 91,7 % |
| Из ответивших переведено верно | 88,8 % |
| Новый заказ в правильный отдел | 67 % |
| Вопрос по заказу в сопровождение | 86 % |

Доля звонков с замечаниями по разбору живых волн: 36 % в третьей волне, 10 % в
четвёртой. Удвоение корпуса даёт около одного процента; главный рычаг оказался
в ручной разметке повторных обращений и в формулировках базы знаний.

## Что оказалось важным на практике

**Одной формулировки на тему мало.** С единственным вариантом порог отсекал
больше половины живой речи. Рабочий минимум — 12–16 формулировок на тему, и
для сантехники, электрики и сборки мебели это должны быть разные темы с разными
вопросами: общий вопрос «сантехника, электрика, мебель?» клиенты считают
непониманием и бросают трубку.

**Короткая реплика тонет в соседях.** «По поводу сборки кухни» по корпусу
похожа на «по поводу ремонта посудомойки»: служебные слова перевешивают тему.
Кодирование только содержательных слов не помогло (замерено: 88,9 против
88,8 %), помогают формулировки в базе знаний.

**Одно слово «оператор» — это просьба, а не шум.** Защита от пустых реплик
требует двух содержательных слов и не пускает такое в корпус; формулировки базы
знаний эту защиту обходят.

**Автоответчик умеет сказать «нет».** Голосовой ассистент абонента повторяет
наш вопрос «ответьте да, если решено, или нет», и поиск слова «нет» в тексте
засчитывает отказ. Разбирать ответ надо целиком: вся реплика из слов согласия
или вся из слов отказа, иначе переспрос.

**Пустое распознавание — не отказ.** Щелчок громкой связи даёт отрезок короче
0,1 секунды и пустую строку; раньше это трактовалось как «вопроса нет в базе».
Теперь бот молча слушает дальше, а переспрашивает только распознанный обрывок.

**Процесс обязан умирать мгновенно при обрыве канала.** Иначе зомби-процессы
копятся и роняют станцию. Сказать об обрыве основной скрипт не может: для этого
Asterisk запускает на разорванном канале отдельный скрипт «последней воли».

**Обратный звонок — только по своей вине.** Перезвон назначается, если клиент
остался без ответа из-за отказа на нашей стороне. Сброс клиента перезвона не
даёт, иначе достаточно насбрасывать сотню звонков.

**Две станции — два uniqueid.** Станция бота живёт отдельно от основной, и её
идентификаторы звонков в CDR основной станции не существуют. Всё, что ищет звонок
по uniqueid, для обращений бота должно искать по телефону и времени.

**Файл на Linux — только с LF.** Скрипт, скопированный с Windows с CRLF, ломает
shebang, и станция сбрасывает звонок без единой строки в логе сервиса.

## Проверки

```bash
py -3.12 -m pytest ai_assistant/tests -q
```

675 тестов: логика диалога, корпусное голосование, разбор посылок базы знаний,
детектор речи, синтез и библиотека голосов, клиент AGI. Отдельные тесты стерегут
совместимость с Python 3.9 на станции и самодостаточность скрипта обрыва.

## Структура

```
ai_assistant/service/   речевой сервис: диалог, база знаний, kNN по корпусу, распознавание, голос, VAD
ai_assistant/agi/       тонкий клиент для Asterisk и скрипт обрыва связи (Python 3.9)
ai_assistant/tests/     тесты
docs/                   спецификации, планы и отчёты по этапам
sql/                    схема и наполнение справочников ERP
tools/                  сбор корпуса, разметка, индекс kNN, библиотека голосов, замеры
```

## Ограничения

Проект писался под конкретную телефонию и ERP: часть кода говорит на языке этой
предметной области — телефонные направления, типы оборудования, обращения.
Универсальным решением он не является и таким не задумывался.
