# Речевой контур ассистента: запуск и обслуживание

Обзор проекта и принятые решения: `README.md` в корне. Здесь только то, что нужно, чтобы поднять сервис,
обновить данные и выложить скрипт на станцию. Состояние на 12.11.2026.

Две части:

- **Сервис** (`ai_assistant/service/`): постоянно работающий демон на виртуалке `10.20.0.10`, Windows,
  Python 3.12. Держит gRPC-поток распознавания и HTTP-ручки диалога и синтеза.
- **AGI-клиент** (`ai_assistant/agi/`): тонкий скрипт на станции Asterisk, Python 3.9. Гонит звук звонка в
  сервис и исполняет то, что тот прикажет. Рядом скрипт обрыва связи `ai_assistant_last_will.py`.

Питон вызывается как `py -3.12`: голый `python` в Windows часто оказывается заглушкой Microsoft Store.

## Запуск сервиса

```powershell
py -3.12 -m pip install -r ai_assistant/requirements.txt
```

Сервис запускается файлом `ЗАПУСК СЕРВИСА.bat` из корня. В нём лежат все боевые настройки с объяснением
каждой, и это единственный источник значений: таблицу настроек в документах не ведём, она расходится.

Что важно знать про настройки:

- Умолчания в `service/config.py` не равны боевым. В коде движок `vosk`, пауза конца реплики 1500 мс,
  тишина 15000 мс, ярус намерения выключен. В бою `gigaam` (модель `v3_rnnt`), 1000 мс, 5000 мс, ярус включён.
  Запуск мимо bat поднимет другую версию поведения.
- Выключатели пишутся словом (`нет`, `net`, `выкл`, `off`, `none`, `-`), а не пустотой: `set VAR=` в cmd
  переменную удаляет, и конфиг берёт умолчание.
- Что реально поднялось, видно в строке `СБОРКА` в `logs/aia.log`: коммит, хэши модулей, модели
  распознавания, все пороги, серая зона, ярус, предел фраз, голос, индекс корпуса.

Полный старт занимает около 35 секунд: основное время едят эмбеддер базы знаний, детектор речи и синтез.
Пока в логе нет строки `Uvicorn running on http://0.0.0.0:8080`, ручки не отвечают.

Проверка живости: `curl http://10.20.0.10:8080/health`. Там же возраст посылки базы знаний,
предупреждения приёмки и счётчик замков категорий, сработавших впустую.

## База знаний

Содержимое ведётся в ERP и приезжает в сервис посылкой раз в десять минут (`POST /knowledge`), копия лежит
на диске и в `feed_archive/`. Схема справочников и формат посылки: `docs/СПЕК-этап2-справочники.md`.

## Записанные голоса

Голоса `voice-a`, `voice-b`, `voice-c`: клоны студийных записей операторов
(CosyVoice 3), синтезированные на GPU-сервере и отобранные распознаванием. В бою видеокарта не нужна: фразы
лежат готовыми файлами в `ai_assistant/voices/<голос>/<ключ>.wav` (8 кГц) с `index.tsv`. Голос выбирается в ERP
в группе линий.

- Ключ файла считается по тексту фразы из посылки. Любая правка текста в ERP означает «записи нет».
- Набор может быть неполным: фразу, которой нет в библиотеке, озвучивает запасной синтез (Vosk-TTS, диктор
  `s3`), остальные звучат записью, недостающее пишется в лог. Правила «весь набор или никак» больше нет.
- Отпечаток библиотеки считается по содержимому файлов и входит в подпись звука: станция перекачает файлы сама.

Новая фраза: синтез на GPU-сервере, затем локально

```powershell
py -3.12 tools/build_voice_library.py --source <папка с дублями> --phrases <фразы.tsv>
py -3.12 tools/merge_voice_library.py
```

и перезапуск сервиса. Тексты в TSV должны совпадать с ERP буква в букву.

## Корпус реплик

Индекс живых реплик с известным исходом звонка, по которому бот выбирает направление
(`service/corpus_knn.py`). Файл `ai_assistant/corpus_index.npz` копируется на машину сервиса руками и
подхватывается при перезапуске; в лог пишется «Корпус реплик: N реплик».

```powershell
py -3.12 tools/build_corpus.py --workers 5 --torch-threads 2 --limit 50000   # ночь, см. ЗАПУСК СБОРА КОРПУСА.bat
py -3.12 tools/build_corpus_index.py                                          # dataset/corpus.jsonl -> corpus_index.npz
```

Каждое решение видно в логе строкой `CORPUS direction=… confidence=… decided_by=…` с тремя ближайшими репликами.

## Выкладка на станцию

Только скриптом, руками через `scp` не копировать:

```powershell
.\tools\deploy_agi.ps1 -PwFile <файл с паролем станции> -DryRun
.\tools\deploy_agi.ps1 -PwFile <файл с паролем станции>
```

Скрипт проверяет совместимость с Python 3.9, делает бэкап, копирует во временное имя, компилирует питоном
станции, подменяет одним переименованием и проверяет права 755. Файлы с CRLF отвергает: такой shebang рвёт
звонок без единой строки в логе сервиса. Трогает только два наших файла.

Диалплан, сеть, переключатели перевода и обращений, откат: `ai_assistant/РАЗВЁРТЫВАНИЕ.md`.

## Замеры и разбор

- Линейка: `py -3.12 tools/measure_live.py --only-live`. Правки базы знаний мерить с `--compare`, иначе
  метрика произносимого текста не считается.
- Регресс по разобранным волнам: `py -3.12 tools/regress_waves.py` (запускать с настройками из bat).
- Реплей записи звонка через детектор и распознавание: `tools/replay_call.py`.
- Реплики, как их услышало распознавание, и поток звонка целиком: `debug_audio/` (хранение 14 дней, 1024 МБ).
- Тайминги: `curl http://10.20.0.10:8080/metrics`.
