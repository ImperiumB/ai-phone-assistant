# Справочники ERP и посылка базы знаний

Состояние на 12.11.2026. Исходная спецификация этапа 2 (14.08.2026) выполнена и сокращена до того, что
осталось правдой; полный текст есть в истории git.

## Справочники

Коды сверены с метаданными ERP (`SOURCES/METADATA/Dictionaries.xmd`).

| Справочник | Таблица | Код | Что хранит |
|---|---|---|---|
| База знаний виртуального помощника | `AI_KNOWLEDGE_BASE` | 56446 | Тема: каноничный вопрос, уточняющий вопрос, ответ при согласии, сценарий, тип оборудования |
| Формулировки базы знаний | `AI_KB_PHRASES` | 56447 | Как ту же тему называют живые люди. Уходит, см. ниже |
| Сценарии виртуального помощника | `AI_SCENARIOS` | 56445 | Действие (перевод) и телефонное направление |
| Разметка обращений AI-ассистента | `AI_REQUEST_REVIEW` | 56461 | Строка на каждое обращение бота для разбора |

Поля записи базы знаний: `QUESTION`, `CLARIFYING_QUESTION`, `POSITIVE_REPLY`, `SCENARIO_ID`,
`EQUIPMENT_TYPE_ID`, `IS_FROM_BOT`, `NOT_ACTIVE`.

Правила, которые держат поведение бота:

- **Запись без уточняющего вопроса в поиске не участвует** и в посылку не попадает. Иначе заготовка, которую
  бот сам завёл из неузнанного вопроса (`IS_FROM_BOT = 1`), совпадает сама с собой на следующем звонке.
- Записи выключаются через `NOT_ACTIVE`, а не удаляются: на них ссылается разметка обращений.
- Номер перевода в сценарии не хранится, он берётся из телефонного направления.
- Голос, служебные фразы и списки согласия и отказа лежат в «Группах линий» (`LINE_GROUPS`, поля `AI_*`),
  а не в записях базы знаний. Формат списков: одна формулировка на строку.
- У каждой записи должны быть формулировки двух видов: запрос услуги и описание поломки. С одной
  формулировкой порог отсекает больше половины живой речи, рабочий минимум 12-16 на тему.

## Формулировки переезжают в табличную часть записи

С 12.11.2026 (UL-19389) в ERP есть таблица `AI_KB_TO_PHRASES`: табличная часть записи базы знаний с колонками
`KNOWLEDGE_BASE_ID`, `PHRASE`, `IS_FROM_BOT`. Ключ строки это пара «запись и текст», колонки `ID` нет.
1018 формулировок скопированы. Посылка пока собирается из старой `AI_KB_PHRASES`.

Что менять при переключении:

- запрос формулировок в обработчике посылки ERP 15424 (`FROM AI_KB_PHRASES … ORDER BY P.KNOWLEDGE_BASE_ID, P.ID`:
  сортировку по `ID` заменить, её в новой таблице нет);
- генераторы SQL: `tools/expand_knowledge_base.py`, `tools/export_knowledge_base.py`,
  `tools/expand_bare_repair.py`, `tools/short_forms_check.py` и их тесты;
- выгрузку `dataset/kb_phrases_now.tsv`, которую читают линейки;
- новые скрипты в `sql/`: формулировка задаётся парой «запись и текст», а не номером строки.

Код сервиса не меняется: он таблицу не читает, формулировки приходят ему полем `phrases`.

## Доставка в сервис

Обработчик ERP 15424 собирает справочники в JSON и отправляет `POST http://<сервис>:8080/knowledge`: роботом
раз в десять минут и кнопкой с формы. ERP толкает, а не сервис забирает, чтобы не трогать службу, через
которую идут живые звонки классического бота.

Одна запись посылки:

```json
{
  "id": 1,
  "question": "стиральная машина не отжимает",
  "phrases": ["стиралка машинка сломалась", "стиралка потекла"],
  "clarifying_question": "Правильно я понял, что вас интересует ремонт стиральной машины?",
  "positive_reply": "Соединяю вас со специалистом по ремонту стиральных машин, оставайтесь на линии",
  "equipment_type_id": 12,
  "equipment_type": "Стиральные машины",
  "scenario_id": 1,
  "telephone_direction_id": 53,
  "redirect_exten": "7105"
}
```

Кроме `records` в посылке едут настройки групп линий (`line_groups`: голос, служебные фразы, списки согласия
и отказа) и `generated_at`. Точный разбор и проверки: `ai_assistant/service/knowledge_feed.py`.

Поведение приёмной ручки:

- Кривая посылка отвергается целиком с кодом 400: частично применять нельзя.
- Пока идёт пересчёт эмбеддингов, звонки обслуживаются старым индексом, подмена одной операцией в конце.
- Посылка сохраняется на диск и в `feed_archive/` (10 последних). При старте сервис поднимает копию с диска.
- `GET /health` показывает возраст данных, предупреждения приёмки и замки категорий без записей.
- Проверки подлинности на ручке нет: сеть внутренняя. Известный риск.

Присланные настройки (голос, фразы) перекрывают значения из пускового файла. Движок распознавания, пороги и
паузы по-прежнему берутся из `ЗАПУСК СЕРВИСА.bat`. Порог близости сознательно не вынесен в справочник:
неверная правка ломает бота молча.
